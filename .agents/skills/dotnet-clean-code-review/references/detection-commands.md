# Candidate detection for Codex

## Tool and scope setup

Use `git` for local diff discovery and `rg` for C# candidate searches. PCRE2 is not required.
Use the host's actual shell: the Bash arrays below are Bash-only; do not paste them into PowerShell.
On PowerShell, construct an array of arguments and invoke `rg @args`; capture `$LASTEXITCODE` immediately.

Prefer small batches of explicit, existing scoped files over scanning unrelated code. Quote paths and separate them from options with `--`. All examples run from the repository root. Replace the example paths with the real scope. For repository-wide scans, use `.` and filter generated/vendor paths before reading.

```bash
git rev-parse --show-toplevel
rg --version

files=( 'src/Example.cs' 'src/Another Example.cs' )
common=( --line-number --with-filename --color never --glob '*.cs'
  --glob '!**/bin/**' --glob '!**/obj/**'
  --glob '!**/*.g.cs' --glob '!**/*.g.i.cs'
  --glob '!**/*.Designer.cs' )
```

Do not run a file-array search if the array is empty: `rg` can otherwise wait on stdin or scan the wrong scope. Adapt exclusions based on actual project metadata and `<auto-generated>` markers; EF migrations are excluded only if generated and not explicitly requested.

`rg` exit 0 means matches; exit 1 means no matches; other exit codes mean failure. No-match output only completes that candidate pass; it is not a semantic PASS. Capture stderr. Avoid piping into `head` or suppressing errors using `|| true`. If output is truncated, rerun smaller batches until every candidate is available.

## Git scope — local changes

Read these NUL-delimited lists and take their union; keep existing, owned `.cs` files. The first two include index/worktree changes and the third includes untracked non-ignored files. Inspect the corresponding diffs. Renames require reading the new path and comparing the old path; deleted files are context only.

```bash
git diff --name-only -z --diff-filter=ACMRTUXB
git diff --cached --name-only -z --diff-filter=ACMRTUXB
git ls-files --others --exclude-standard -z
git diff --no-ext-diff --no-textconv --unified=3 -- '*.cs'
git diff --cached --no-ext-diff --no-textconv --unified=3 -- '*.cs'
```

For unusual path names, parse bytes/NULs using available tooling rather than splitting on spaces/newlines.

## Git scope — PR / branch

Determine the base from the user, PR metadata or the default remote HEAD:

```bash
git symbolic-ref --quiet refs/remotes/origin/HEAD
git branch --list
git branch --remotes
```

The symbolic-ref command can fail when the metadata is absent. That does not establish `main` or `master`. A feature branch's tracking ref is not necessarily its PR target. Validate the chosen local ref, then use the merge base. This Bash example requires setting `base` to a known, validated ref:

```bash
base='origin/main' # EXAMPLE ONLY: replace with the discovered PR base.
git rev-parse --verify "${base}^{commit}"
merge_base=$(git merge-base "$base" HEAD) # Check exit status before continuing.
git diff --name-only -z --diff-filter=ACMRTUXB "$merge_base" HEAD -- '*.cs'
git diff --no-ext-diff --no-textconv --unified=3 "$merge_base" HEAD -- '*.cs'
```

Stop and report a scope blocker if there is no reliable base or merge base. Do not fetch in a read-only review without authorization. A shallow clone may require missing history to be supplied. Branch diffs compare commits; if the working tree is dirty, distinguish current source from the committed HEAD snapshot. Review HEAD using `git show HEAD:<path>` when local changes were not requested, or explicitly include local changes in scope.

## D1 — Async and awaitable declarations

```bash
rg "${common[@]}" -e '\basync\s+void\b' -- "${files[@]}"
rg "${common[@]}" -e '\b(async|Task|ValueTask|CancellationToken)\b' -- "${files[@]}"
```

Read full declarations, bodies and call sites. This catches evidence without pretending to parse parameter lists. Inspect both declarations and token propagation. Keep genuine event handlers and fixed interface/override names. Do not whitelist all methods named Handle/Execute/Invoke automatically. Do not exclude entire GraphQL/endpoint files; check each fixed contract individually. Cancellation may come from request/job lifetime even without a method parameter. Unowned fire-and-forget execution is a lifecycle risk, not an automatic exception.

## D2 — Collection contracts

```bash
rg "${common[@]}" -e '\b(IEnumerable|IAsyncEnumerable|IReadOnlyList|IReadOnlyCollection|IQueryable)\s*<' -e '\byield\s+return\b' -- "${files[@]}"
```

Separate parameters from return types. Determine whether results are lazy, materialized, streaming or queryable. A list exposed as IEnumerable does not rerun database work merely because it is enumerated twice. Recommend materialization only with evidence and bounded data.

## D3 — Boolean data versus mode flags

```bash
rg "${common[@]}" -e '\bbool\b' -- "${files[@]}"
```

Inspect method signatures and calls, not just every bool property/local variable. Positional records and primary-constructor domain data are not mode flags. Named arguments may improve clarity without a breaking signature change.

## D4 — Vague responsibility names

```bash
rg "${common[@]}" -e '\b(class|record|struct|interface)\s+[A-Za-z0-9_]*(Manager|Helper|Helpers|Utils|Utility|Utilities)\b' -- "${files[@]}"
```

Framework ownership and actual domain responsibility matter. Generic framework Identity managers are not user-code naming violations.

## D5 — Regions

```bash
rg "${common[@]}" -e '^\s*#region\b' -- "${files[@]}"
```

Inspect cohesion and repository style; do not claim every region requires class extraction.

## D6 — Interfaces and real usage

```bash
rg "${common[@]}" -e '\binterface\s+' -- "${files[@]}"
```

For each scoped interface or an interface affected by a changed class, identify the exact qualified symbol. Search references across owned source AND tests, outside the review scope if necessary for context:

```bash
rg --line-number --with-filename --color never --glob '*.cs' \
  --glob '!**/bin/**' --glob '!**/obj/**' -w -e 'IExamplePort' -- .
```

`IExamplePort` is an example, not a repo assumption. Read type base lists, indirect inheritance, explicit members, partial/generic types, DI registrations, decorators and test doubles. Symbol-aware tooling is preferred when available. Count actual implementations and consumers, NOT files containing the name. Names can collide across namespaces. Reflection/source generation and external consumers limit what a text search proves. Never delete an interface on a low reference count alone.

## D7 — Inheritance graph

```bash
rg "${common[@]}" -e '\b(class|record)\s+' -- "${files[@]}"
```

Read multiline base lists and primary constructors. Resolve whether each base-list symbol is a class or interface from declarations/metadata, never from the leading I. Follow class bases across owned source to establish the actual chain. Three owned types A -> B -> C are a depth candidate. Framework bases are context. Empty regex output does not prove absence of a hierarchy; generated and external bases can remain unresolved. Recommend composition only with concrete coupling/maintenance evidence.

## D8 — Manual readability coverage

Read all scoped files/changed members against the twelve readability categories, including members absent from all matches. Log skipped files as incomplete coverage. No regex can establish responsibility or readability.
